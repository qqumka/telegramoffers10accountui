# Управление с телефона без окна приложения

`bot_runner.py` работает без Qt, Tkinter и графического экрана. Окно приложения
можно не запускать. Сам скрипт должен постоянно работать: на VPS или включённом
компьютере. Выключение компьютера, сон Mac или завершение процесса останавливает
бота. Для работы 24/7 используйте VPS.

Администратор по умолчанию: **8957889799**. Другие пользователи и групповые чаты
игнорируются. Токен не встроен в исходники. Перевыпустите опубликованный токен
через BotFather и используйте новый. Не запускайте GUI и бота одновременно с
одной папкой `data`: сессии должны использоваться одним процессом.

## Первый запуск на Mac или Linux

Скачайте новый ZIP целиком. Сохраните свою папку `data` из предыдущей версии.
В терминале, находясь в папке проекта:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-bot.txt
.venv/bin/python bot_runner.py
```

Скрипт спросит API ID, API Hash и токен BotFather. Секретные поля вводятся скрыто
и не сохраняются в файлы настроек. API ID и API Hash нужны для личных аккаунтов,
одного токена бота для поиска и отправки от личных аккаунтов недостаточно.
Если уже есть авторизованные `data/account_1.session` и другие слоты, скрипт
подключит их автоматически. Откройте бота в Telegram, нажмите **Start**.

Если сессий ещё нет, сначала авторизуйте аккаунты локально:

```sh
.venv/bin/python bot_runner.py --login 1
.venv/bin/python bot_runner.py --login 2
```

Введите номер телефона, код Telegram и пароль 2FA в терминале. Не пересылайте
коды и пароли в бот. После входа скрипт сохранит сессию и завершится. Затем
запустите `bot_runner.py` без `--login`. Для переноса на VPS перенесите свою
папку `data` приватным способом, не публикуя сессии в GitHub или чате.

## Управление

В боте появляется клавиатура:

- **Запустить** — сканирование с текущими подарками и режимом.
- **Пауза** — пауза / продолжение. **Стоп** — отмена текущей очереди и поиска.
- **Статус** — режим, аккаунты, число поисковых слотов и последний итог рынка.
- **Аккаунты** — включение поиска по слотам и подтверждаемый выход из сессии.
- **Подарки** — галочки коллекций, все коллекции, постраничный список.
- **Логи** — последние 15 событий. Полный журнал остаётся в `data/activity.log`.
- **Пробное** — отправка заданного пробного сообщения после подтверждения.
- **Режим** — предпросмотр или реальные предложения с подтверждением.

Команды: `/start`, `/run`, `/pause`, `/stop`, `/status`, `/accounts`, `/connect`,
`/gifts`, `/refresh`, `/logs`, `/test`, `/mode`. После первого подключения
обновите каталог через `/refresh`. После перезапуска режим всегда
**предпросмотр**; отправка включается через **Режим** с одноразовым подтверждением.

Первый полный круг по-прежнему без сообщений, продавцы не повторяются,
аккаунты делят коллекции. Общий интервал между попытками отправки **15 секунд**:
первый аккаунт → 15 секунд → второй → 15 секунд → следующий. Он применяется и
к пробным сообщениям, не сбрасывается остановкой и повторным запуском внутри
одного процесса. Сообщения самого управляющего бота этим интервалом не ограничены.
Неудачные сообщения автоматически не повторяются. Правило PeerFlood 3 подряд
сохранено. Изменение подарков действует со следующего запуска поиска.

## Запуск как сервис на Linux VPS

Установите проект в `~/telegramoffers10accountui` и авторизуйте сессии. Создайте
приватный файл `~/.config/telegram-offers/bot.env` с правами `600`, заполнив
свои значения:

```text
TG_API_ID=ваш_числовой_id
TG_API_HASH=ваш_api_hash
TG_CONTROL_BOT_TOKEN=новый_токен_бота
TG_CONTROL_ADMIN_ID=8957889799
TZ=Asia/Almaty
```

Этот файл хранится на вашем сервере вне репозитория. Значения не присылайте в чат.
В неинтерактивном режиме переменные обязательны; скрипт не будет ждать ввода.

```sh
mkdir -p ~/.config/systemd/user
cp deploy/telegram-offers.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now telegram-offers
systemctl --user status telegram-offers
```

Чтобы пользовательский сервис оставался после выхода из SSH, администратор
сервера включает linger для вашего пользователя:

```sh
sudo loginctl enable-linger "$USER"
```

Остановка: `systemctl --user stop telegram-offers`. Журнал запуска:
`journalctl --user -u telegram-offers`. При HTTP 401 проверьте токен, при 409
убедитесь, что нет второго процесса бота или активного webhook. Скрипт сам
не удаляет существующие webhook и не запускает второй экземпляр с той же `data`.

Проверки без Telegram: `.venv/bin/python -m unittest test_offers test_bot_runner -v`.
Для тестов Qt дополнительно установите обычный `requirements.txt`.
